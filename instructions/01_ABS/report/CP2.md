# Checkpoint 2 報告：ABS RV32IM 實作

## 1. 本次目標
本 Checkpoint 的目標為使用標準 RISC-V RV32IM 組合語言實作 `ABS`（絕對值）函式，並在 Ripes 5-Stage Pipeline 模擬器上運行 10 組測試向量，精確統計靜態指令數、動態指令數與分支數等效能指標。

## 2. 設計內容
`ABS` 指令為一元運算，其語意為 `rd = |rs1|`，輸入與輸出均為 32 位元有符號整數。為了避免控制阻害（Control Hazard）導致流水線沖刷（Pipeline Flushing），本次組合語言採用無分支（Branchless）架構：

1. `srai t0, a0, 31`：算術右移 31 位元提取符號遮罩（正數/零為 `0x00000000`，負數為 `0xFFFFFFFF`）。
2. `xor a0, a0, t0`：進行 `XOR` 運算（正數保持原樣，負數轉換為 1 的補數）。
3. `sub a0, a0, t0`：減去遮罩值（正數減 `0` 不變，負數減 `-1` 相當於加 `1` 轉為 2 的補數）。

在邊界與溢位處理上，當 `rs1 = -2147483648` (`INT32_MIN` / `0x80000000`) 時，由於正數最大值僅能表示至 `2147483647` (`INT32_MAX`)，絕對值運算會發生 32-bit 二補數溢位；依據課程規格，此狀況取低 32 位元 wrap-around，結果仍為 `-2147483648`。

## 3. 結果與分析
模擬環境設定為 Ripes 5-Stage RISC-V Processor，執行包含 10 組測試向量（含 `INT32_MIN` 與 `INT32_MAX` 等邊界值）之測試程式，執行結果如下表：

| 統計項目 | ABS 核心函式 (`abs_rv32im`) | 全程式 Testbench 總計 |
|---|---|---|
| 靜態指令數 (Static Instructions) | 3 條 (`srai`, `xor`, `sub`) | 14 條 |
| 動態指令數 (Dynamic Instructions) | 30 條 (3 * 10 次呼叫) | 107 條 |
| 靜態分支數 (Static Branch Count) | 0 條 | 1 條 (`beq`) |
| 動態分支數 (Dynamic Branch Count) | 0 次 | 11 次 |
| 總執行週期數 (Total Cycles) | - | 175 cycles |
| CPI (Cycles Per Instruction) | - | 1.64 |
| IPC (Instructions Per Cycle) | - | 0.611 |

**數據分析**：`abs_rv32im` 函數內部靜態與單次動態指令數皆為 3 條，且分支數為 0 次。因完全消除函數內部的分支跳轉，成功免除分支預測失敗帶來的 Pipeline Flush 懲罰，驗證了無分支設計在流水線處理器上的效能優勢。

## 4. 遭遇的問題與解法
在撰寫組合語言時，若採用傳統條件跳轉指令（如 `bltz`）來處理負數，當遇到負數時會觸發分支跳轉，在 5-stage pipeline 中會產生 2 個週期的 Branch Penalty（Pipeline Flush）。為解決此問題，我們改為無分支（Branchless）的位元運算架構，將 `abs_rv32im` 內部的分支數降為 0，成功消除所有因條件判斷產生的控制阻害。

## 5. 白話說明
算絕對值就像幫數字量距離。如果用傳統條件判斷，就像每次看到數字都要停下來問「你是負數嗎？」，回答「是」才轉向去拆掉負號，這會讓後面排隊的指令（流水線）全部卡住停頓。無分支方法就像給每個數字通過一個自動通道：正數通過時通道什麼都不做，負數通過時通道自動順手把它反轉加一變正數。大家都不用停下來回答問題，順暢通過，效率最高。

# Checkpoint 2 報告：ABS RV32IM 實作

## 1. 本次目標
本 Checkpoint 的目標為使用標準 RISC-V RV32IM 組合語言實作 `ABS`（絕對值）函式，並在 Ripes 5-Stage Pipeline 模擬器上運行 `10` 組測試向量，精確統計靜態指令數、動態指令數與週期數等效能指標。

## 2. 設計內容
在 RV32IM 組合語言中，採用無分支（Branchless）算術邏輯實作 `ABS` 函式：
1. `srai t0, a0, 31`：提取 `a0` 符號位元並擴充至全暫存器（正數為 `0x00000000`，負數為 `0xFFFFFFFF`）。
2. `xor a0, a0, t0`：若為負數則進行全位元反轉（1's complement）。
3. `sub a0, a0, t0`：減去 `-1`（相當於加 `1`，完成 2's complement 取補數）。
4. `ret`：返回呼叫處。

此設計可涵蓋一般正負數與 `-2147483648`（`INT32_MIN`）之 32-bit wrap-around 溢位邊界需求。

## 3. 結果與分析
在 Ripes 5-Stage Pipeline 處理器上執行 10 組測試向量，量測數據如下表：

| 測量項目 | 全程式總計 (Total Testbench) | ABS 函式本體 (abs_rv32im) |
|---|---|---|
| **靜態指令數 (Static Insts)** | `16` 條 | `4` 條 (`srai`, `xor`, `sub`, `ret`) |
| **動態指令數 (Dynamic Insts)** | `107` 條 | `30` 條 (核心算術) / `40` 條 (含 `ret`) |
| **總執行週期數 (Cycles)** | `175` cycles | - |
| **平均指令週期數 (CPI)** | `1.64` | - |
| **靜態/動態分支數 (Branches)** | `1` 條 (靜態) / `11` 次 (動態) | `0` 條 (無分支架構) |

**計數與數據修正說明**：
- **靜態指令數修正**：全程式包含主測試架構與函式，其中 `la` 虛擬指令編譯後展開為 `auipc` 與 `addi` 共 `2` 條機器指令，加上主程式其餘指令（`10` 條）與 `abs_rv32im` 函式（`4` 條，含 `ret`），實際總靜態指令數為 `16` 條。
- **動態指令計數規則說明**：`abs_rv32im` 核心算術指令為 `3` 條 (`srai`, `xor`, `sub`)，執行 `10` 次測試共 `30` 條動態指令；若將函式返回控制指令 `ret` 一併計入，每次呼叫為 `4` 條，共累計 `40` 條動態指令。

## 4. 遭遇的問題與解法
在統計靜態指令數時，初次計算未考量到 RISC-V 虛擬指令（Pseudo-instruction，如 `la`）會被組譯器展開為 `auipc` + `addi` 兩條實體指令，導致計算結果與反組譯碼不一致。後經查看 Ripes 反組譯視窗（Disassembled code）進行校正，確認全程式總靜態指令數為 `16` 條。

## 5. 白話說明
ABS 函式就像是測量數字到 0 的距離。這次我們用 RISC-V 組合語言的「無分支技巧」來算絕對值，不需要用判斷式跳轉（Branch），只靠三步位元運算就直接算出正數結果。雖然本專題 CP2 階段僅量測無分支版本，但此設計在理論上能避免 5-stage 流水線架構因分支猜錯而產生的 Flush 週期開銷。

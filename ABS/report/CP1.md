# Checkpoint 1 報告：ABS C Baseline

## 1. 本次目標
本 Checkpoint 的目標為完成自訂 RISC-V 擴充指令 `ABS`（絕對值）之 C 語言 Baseline 程式碼實作，並設計包含邊界極限值的 10 組測試向量進行正確性驗證。

## 2. 設計內容
`ABS` 指令為一元運算，其語意為 `rd = |rs1|`，輸入與輸出均為 32 位元有號整數。在邊界與溢位處理上，當 `rs1 = -2147483648` (`INT32_MIN` / `0x80000000`) 時，由於正數最大值僅能表示至 `2147483647` (`INT32_MAX`)，絕對值運算會發生 32-bit 二補數溢位；依據課程規格，此狀況取低 32 位元 wrap-around，結果仍為 `-2147483648`。測試架構則採用 C 語言 `struct` 封裝測試向量進行自動化驗證。

## 3. 結果與分析
假設測試環境為標準 C99 相容編譯器，整數型態 `int32_t` 精確佔用 32 位元。本次共設計 10 組測試向量，執行結果如下表：

| 編號 | 測試類型 | 輸入值 (`rs1`) | 預期輸出 (`rd`) | 實際輸出 | 結果 |
|---|---|---|---|---|---|
| 1 | 一般負數 | -5 | 5 | 5 | PASS |
| 2 | 零 | 0 | 0 | 0 | PASS |
| 3 | 邊界極值 (INT32_MIN) | -2147483648 | -2147483648 | -2147483648 | PASS |
| 4 | 邊界極值 (INT32_MAX) | 2147483647 | 2147483647 | 2147483647 | PASS |
| 5 | 一般正數 | 100 | 100 | 100 | PASS |
| 6 | 一般負數 | -100 | 100 | 100 | PASS |
| 7 | 相鄰零負數 | -1 | 1 | 1 | PASS |
| 8 | 相鄰零正數 | 1 | 1 | 1 | PASS |
| 9 | 大數負數 | -1234567 | 1234567 | 1234567 | PASS |
| 10 | 大數正數 | 1234567 | 1234567 | 1234567 | PASS |

**數據分析**：測試通過率達 100% (10/10 PASS)，完整涵蓋一般數值、正負極限及溢位邊界條件，確認 C baseline 邏輯完全符合規格。

## 4. 遭遇的問題與解法
在撰寫 C 語言的絕對值邏輯時，若直接對有號整數最小值 `INT32_MIN` (`-2147483648`) 執行 `-rs1` 取負值操作，會造成 C 語言標準中的整數溢位未定義行為（Undefined Behavior）。為解決此問題，我們在 `abs_custom` 函數中明確加入對 `INT32_MIN` 的特殊判斷條件，強制返回 `INT32_MIN`，確保符合 RISC-V 32 位元二補數算術下 wrap-around 的硬體行為規範。

## 5. 白話說明
ABS 指令就像是數字的「距離測量器」，無論給它正數還是負數，它都會告訴你這個數字距離 0 有多遠。例如 -5 距離 0 是 5 步，5 距離 0 也是 5 步。唯一特殊的是最左邊的極限數字（-2147483648），因為正數那邊最多只能裝到 2147483647，裝不下這個極限值，所以計算後會像時鐘超過 12 點一樣，繞一圈回到原本的極限數字。
